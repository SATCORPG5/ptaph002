what costs extra

how changes are handled after approval

A revision = changes to existing work already delivered
Examples of revisions:
changing colors
adjusting layout spacing
moving buttons
updating text
swapping images
minor UI tweaks
small usability adjustments
These are normal refinements.

These are new features, not revisions:
NOT revisions:

building new database tables

passwords never stored in plain text

USER ROLES
Creator

manage creator card
Cannot:
access admin dashboard

change system configuration
view audit logs

IF user.role == "creator"
allow edit own profile

IF user.role == "admin"
allow edit all profiles

IF user.role == "superadmin"
allow full system access

Why RBAC Matters
Without it:
creators could access admin tools
private notes could leak
system integrity breaks

Restricting access to sensitive pages.

User tries to access admin page
↓

↓

↓

Security Layers
Frontend Protection
hides UI elements based on role
prevents navigation to restricted pages

Backend Protection (CRITICAL)
API routes verify role before executing actions
prevents bypassing frontend restrictions

Frontend protection alone is NOT secure.Backend validation is mandatory.

What it is
How passwords are stored, processed, and protected.

Core Rules
A. Password Hashing
passwords are never stored as plain text
converted into irreversible hash values

Recommended requirements:

mix of letters, numbers, symbols
prevent common passwords

time-limited reset tokens
single-use reset links
secure email verification required

Token sent via email
↓

Old sessions invalidated

Why you’re asking:This defines database size, UI complexity, moderation load, and hosting requirements.

500+ (SaaS-level system)
Why it matters:
10 creators = simple CRUD system
500+ creators = search, filters, optimization, pagination, caching

2. Expected growth?
Why you’re asking:This tells you if you’re building a “tool” or a “platform.”
Good answers:
“We’ll stay under 50 creators”
“We expect 10–20 new creators monthly”
“We want to scale to thousands eventually”
Why it matters:
Growth = you must build scalable architecture now
No growth = simpler MVP, cheaper build

3. Public signup or invite-only?
Why you’re asking:Controls security, onboarding flow, and fraud risk.
Options:
Invite-only (agency controlled)
Public signup (platform-style)
Hybrid (apply + approval)
Why it matters:
Public signup = spam protection, verification system needed
Invite-only = simpler auth logic

4. Admin approval required?
Why you’re asking:Defines workflow complexity.
Answers:
Yes (recommended)

approval queue
draft system
status workflow (pending/approved/rejected)
